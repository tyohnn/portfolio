## 채택 — 포트폴리오의 중심

1. **데이터 모델 세대 에세이 (테마)**
   프로젝트 목록보다 먼저 읽히는 중심 글.
   `룰 챗봇 상태(2022) → KG RAG(2023) → 다형 캔버스(2025) → 타입 카탈로그 그래프(2026)`.
   "다형성을 열수록 UX는 살고 정합성은 죽는다 / 도메인을 닫을수록 그 반대"가 이 포폴의 척추다.

2. **에이전틱 워크플로우 에세이**
   Veclix(툴 호출) → 캔버스 협업 → ssota(에이전트가 SoR을 조작, 사람은 승인) → oh-my-docs/never-sleep(에이전트가 제품을 만드는 운영).
   "에이전트에게 일을 시키는 제품"과 "에이전트가 이 레포를 치게 하는 하네스"를 구분한 판단은 흔치 않다.

3. **한계를 프로젝트 카드의 필수 필드**로 두기
   사용자는 이미 한계를 잘 말한다. 사이트 IA에 `한계`를 빼면 평범한 이력 사이트가 된다.

4. **공개 산출물을 앵커로**
   `ssota-labs/ssota`, `oh-my-docs`, `canvasdown`, `spatial-context`, `onlycmd`.
   private 레포는 "이름 + 배운 것"만.

## 넣으면 좋은데 회고가 필요

5. **oh-my-docs / never-sleep-agent / harness-engineering**
   2026 하반기의 실제 손맛. "제품을 만드는 에이전트" 쪽이 채용/투자 모두에 신선하다.
6. **holiday-cfo**
   그래프 SoR을 자기 돈에 적용한 dogfood. 라이프자켓 노션 실험과 이어짐.
7. **크날 반복 납품**
   B2B SaaS 3층 분해의 현장 근거. "에이전시가 하던 번역 비용"을 내가 몸으로 한 이야기.
8. **Fynd KG RAG**
   2026 그래프의 원형. 단, 내 역할이 분명해야 한다.

## 사이트 형태 — 테마 우선으로 채택

타깃은 **채용**. 홈 thesis는 특정 제품이 아니라 오래 붙잡아 온 질문이다.

- 홈: 한 줄 질문 + 데이터 추상화 / 관계·다형성 / Agent SSOT.
- `/themes/data-model`, `/themes/agentic-workflow`, `/themes/b2b-records`,
  `/themes/integrity`, `/themes/harness`: 중심 에세이.
- 연도와 프로젝트는 에세이의 근거 링크이자 하단 타임라인.
- 프로젝트 카드 필드: 바뀐 질문 / 문제 / 모델 / 결정 / 한계 / 스택.
- 영문 토글은 2차로. 먼저 한국어 문장이 굳은 뒤.

## 개발 시 살리면 좋은 장치

- 각 판단 옆에 근거 링크 (노션, 커밋, 레포). 에이전트가 나중에 문장을 검증하기 쉽다.
- "내가 지금 다시 한다면" 한 블록. 2026 회고가 이미 이 형식이다.
- 스크린샷보다 스키마 다이어그램. 이 포폴의 주인공은 UI가 아니라 모델이다.

# 2023

> 상태: 1차. 사용자: **에이전트를 학습하던 시기**. Fynd / Veclix 역할은 본인 회고 기준.

## 한 줄

LLM이 도구를 호출하게 만드는 법을 배우던 해. 초반은 버디파이에서 Vue를 썼고, 이후 Fynd는 여행 에이전트에 지식그래프를, Veclix는 API 툴 계약을 짰다.

## 프로젝트

### 버디파이 — Vue (초반)

스타트업스테이션 동기 팀에 잠깐 합류 (노션: 2023.03–06). 사용자: **Vue.js로 진행**. 채용 스택의 Vue/Nuxt 근거. 제품 한 줄·내 범위는 아직 짧다.

### Fynd — 여행 에이전트 + 그래프 시도

비정형 여행 콘텐츠(유튜브 등)를 정형 장소 데이터로 뽑아 에이전트가 쓰게 하려 했다. 지식그래프 형태로 연결하려는 시도가 있었다.

코드 (`ssota-labs/Fynd-LLM`): Neo4j. 라벨 `Country` / `Locality` / `Keyword` / `Youtube_Channel` / `Youtube_Video` / `Video_Section`. 관계 `BELONG_TO`, `SEARCH_RESULT`, `HAS_SECTION`, `RELATED_TO`. 온톨로지 파일은 없음. 프롬프트는 여행 유튜브 챕터 JSON Schema.

2026 컨텍스트 그래프의 원형으로 쓸 수 있다. 다만 이때는 **학습**이지 완성된 SoR이 아니다. 해커톤 수상 나열은 한 줄 메타만.

### Veclix — 업무자동화 에이전트, Tool 계약

Zapier/N8N류가 아니라, 에이전트가 부를 도구를 **하나의 계약**으로 등록·조회·실행하게 했다. 사용자는 이를 나중에 나온 MCP와 유사한 API 계약으로 회고한다.

코드와 일치:

- `Veclix-BE` `ToolsBase`: `name`, `function_name`, `description`, `tags`, `api_key_required`, `api_owner`, `custom_function`, `design`
- HTTP: `POST /tools`, `GET /tools/all`, `GET /tools`. `user_tools`로 GitHub/Slack OAuth
- `EmployedAgent.tools = ARRAY(String)`
- `Veclix-LLM`: OpenAI function-calling JSON schema (`openai_function_calling`). `FUNCTION_CALLABLE_DICT` + `get_functions_schema(tools)`
- 도구 예: `googleWebSearch`, `slackSendMessage`, `createNewNotionPage`, `get_commit_logs`, `send_mail_through_gmail`, `getKnowledgeFromVdb`, `progressNextTask`

MCP 파일은 없다. 2026 ssota MCP / onlycmd와 대비하면 “툴 스키마를 한곳에 모은다”는 판단이 3년에 걸쳐 반복된다.

### 그 외 (회고 없음, 채용 본문 약함)

라스토리아(텍스트 RPG), RealMate, 뉴바타, 버틀봇 GPT. 학습기 병렬 실험으로만 언급.

## 배운 것

- 에이전트는 채팅이 아니라 **호출 계약**이다. 이름·설명·JSON schema·소유자(API 키)가 있어야 한다.
- 여행처럼 관계가 있는 도메인은 청킹만으로 부족하고, 장소 계층을 그래프로 붙이고 싶어졌다.
- 한 해에 제품이 여러 번 바뀌었다. 채용 서사에서는 “학습 루프”로 묶고, 완성작처럼 쓰지 않는다.

## 고민 / 한계

- 툴 계약은 있으나, 2026처럼 SoR·게이트·서버 권한 층은 아직 없다.
- Fynd 그래프는 추출·적재 스크립트 수준. 카탈로그/정합성 포트는 없음.
- 팍스휴마나 명단에는 대표 연주환·이사 백민기만 있다. 팀 제품을 쓸 때 **내 기여 = 에이전트 학습 / Fynd 그래프 시도 / Veclix 툴 계약**으로 한정한다. 회사 약력을 내 직함처럼 쓰지 않는다.

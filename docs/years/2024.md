# 2024

> 상태: 1차. 사용자: 크날에서 **캐치블로그** — 네이버 검색 크롤, 데이터·크롤 규모가 컸고, cron + functions 배포.

## 한 줄

검색 결과를 매일 적재하는 배치 SaaS. 규모는 큐와 제약조건에서 터졌다.

## 캐치블로그 (크날)

네이버 블로그 키워드 순위·SEO/경쟁 분석. 코드는 네이버 SERP (스마트블록/일반블록). 문서 일부는 Google이라고 적혀 있으나 구현은 네이버.

### 한 일

- 추적 키워드/블로그를 매일 큐에 넣고 (`PAGE_SIZE=1000`), Edge Function이 꺼내 Next API로 팬아웃.
- 워커 6종: SERP, 키워드 볼륨, 블로그 방문자, 블로그 랭크, 트래커 결과 갱신, 카카오 리포트.
- 랭크 갱신은 서버리스 타임아웃을 **5분**까지 올림.
- 동시 upsert 때문에 `serp_results (keyword_id, date)` 중복이 남. UNIQUE 제약 + upsert로 닫음.
- 사용자 회고: 데이터 크기와 크롤 부하가 매우 컸다. cron job, functions 배포.

### 배운 것

- 크롤은 스크레이퍼보다 **적재 계약**이 먼저다. 날짜+키워드 유니크가 없으면 동시 워커가 행을 복제한다.
- 서버리스는 긴 잡을 한 함수에 넣지 못한다. 큐로 쪼개고, 꼭 필요한 경로만 timeout을 연다.
- “매일 전량”은 도메인 로직이 아니라 인프라 제약(동시성, 5분, 시크릿 헤더) 위에서 돈다.

### 한계

- 큐는 Redis가 아니라 **PGMQ**. 재시도·독 관리를 직접 맞춤.
- README는 보일러플레이트. 스펙은 `docs/`에 흩어짐.
- 크날 PM 기간(2024.04–2025.06)의 다른 일(FIM, 임웹)은 아직 카드로 안 씀.

### 스택

Next.js 14, React, TypeScript, Tailwind, Zod, Supabase (Postgres, Auth, Edge Functions), Cheerio, ZenRows, Vercel `maxDuration`, PGMQ.

## 아직 모름

- 실제 일 키워드/행 규모 숫자 (코드에는 1000 배치만).
- Django를 이 해에 썼는지 (스택에는 올려 둠).
